# PLU 実行時カラーパレット API 仕様案

> 状態：初期実装済み。2026-11-20 時点でエンジン・Worker・ホスト・通常表示・CRTへの連携を実装。自動テストは追加済みで、CI結果と実機確認は別途確認する。

## 1. 目的

ゲーム実行中に、既存の 8 色パレットの RGB 値を変更できるようにする。ピクセル面には RGB 値ではなく色番号を保持し、表示時に色番号を RGB へ変換する現在の方式を維持する。

これにより、画面上に描画済みのピクセルも、同じ色番号を使っていればパレット変更だけで一斉に色が変わる。水面・炎・ネオン・星の明滅などを、画像を描き直さずに表現できる。

## 2. API の基本方針

パレット操作は、将来の機能追加を見越して **チェーンメソッド形式** にする。

単発の関数に機能を詰め込むのではなく、ucpl をパレット操作の窓口とし、その配下に操作メソッドを設ける。変更系メソッド（set / setAll / reset）は ucpl 自身を返し、連続して呼び出せる。get は色データを返す。

この形なら、初期版は色の変更と標準パレットへの復元だけに絞りつつ、将来的にパレットセットの切り替え・保存・複製などを追加しやすい。

## 3. 初期 API 案

### 3.1 個別の色を変更する

ucpl.set(index, r, g, b)

- index：変更する色番号。0〜7。
- r：赤成分。0〜255 の整数。
- g：緑成分。0〜255 の整数。
- b：青成分。0〜255 の整数。
- 指定した色番号の RGB 値を変更する。
- 変更は同じフレームの表示に反映する。
- 正常終了時は ucpl を返し、メソッドチェーンを継続できる。
- 引数はすべて必須。範囲外・小数・非数値・不足または過剰引数は RangeError または TypeError とする（具体的な例外型は実装前に統一する）。

例：

~~~js
// 色番号 3 を赤、4 を青、5 を緑にする
ucpl
  .set(3, 255, 0, 0)
  .set(4, 0, 0, 255)
  .set(5, 0, 255, 0);
~~~

### 3.2 パレット全体を一括設定する

ucpl.setAll(colors)

8 色すべての RGB 値をまとめて設定する。引数は 8 要素の配列とし、各要素は [r, g, b] の 3 要素配列とする。各成分は 0〜255 の整数。入力全体を検証してから反映し、1 色でも不正ならパレットを一切変更しない。正常終了時は ucpl を返す。

~~~js
ucpl.setAll([
  [0, 0, 0],
  [30, 20, 60],
  [80, 50, 120],
  [120, 80, 160],
  [160, 120, 200],
  [190, 160, 220],
  [220, 200, 240],
  [255, 255, 255]
]);
~~~

### 3.3 現在の色を取得する

ucpl.get(index)

指定した色番号の現在の RGB 値を { r, g, b } 形式で返す。戻り値はパレット本体と独立した読み取り用の値とし、戻り値を書き換えてもパレットは変更されない。

~~~js
const color = ucpl.get(3);
const nextRed = Math.min(255, color.r + 2);
ucpl.set(3, nextRed, color.g, color.b);
~~~

グラデーションや時間経過による色変化をゲーム側で計算する際に利用できる。get() は ucpl 自身ではなく色データを返すため、チェーン対象外とする。

### 3.4 標準パレットへ戻す

ucpl.reset()

8 色すべてを PLU 標準パレットへ戻す。正常終了時は ucpl を返す。

~~~js
ucpl.reset();
~~~

### 3.5 チェーンの組み合わせ

~~~js
ucpl
  .set(3, 255, 0, 0)
  .set(4, 0, 0, 255)
  .reset();
~~~

この例では最後の reset() によって、途中の変更を含めて標準パレットに戻る。

## 4. 将来の拡張候補

初期版では実装しないが、同じ ucpl の配下に以下の操作を追加できる構造を想定する。

| メソッド候補 | 想定する役割 |
| --- | --- |
| use(name) | 名前や識別子でパレットセットを切り替える |
| save(name) | 現在のパレットをセットとして保存する |
| copy(source, name) | 既存セットを複製する |
| list() | 利用可能なパレットセットを確認する |

例えば、将来的には次のような書き方が考えられる。

~~~js
ucpl
  .use("night")
  .set(3, 255, 0, 0)
  .save("myPalette");
~~~

これは拡張イメージであり、メソッド名・引数・保存先・保存期間・ユーザー定義セットの扱いは未決定。特に save() はゲーム実行中だけの保存なのか、ゲームデータとして永続化するのかを別途設計する。

**パレットセットは、8 色分の RGB 値をまとめた一組のデータとして扱う。** 個別色の変更とセット切り替えは両立できる。セットを切り替えた後に set() で一部の色だけ調整する使い方も想定する。

## 6. 色番号とピクセル面

- ピクセル面は現在どおり 160×144 の Uint8Array とし、各要素は 0〜7 の色番号を保持する。
- ucpl はピクセル面を書き換えない。RGB パレットだけを変更する。
- したがって、既に描画された文字・スプライト・図形も、同じ色番号なら新しい RGB 色で表示される。
- 色番号 0 は通常の不透明色であり、透明を意味しない。
- pcg、spr、BG・MG・FG レイヤーなど既存の色指定は、引き続き色番号を使う。

## 7. 表示側との連携が必要

ゲーム処理は Worker 内で実行される一方、通常表示と CRT 表示はホスト側で行われる。現在の構成では、エンジン内の変更だけでは画面表示側の RGB パレットへ変更を伝えられない。

実装時は次の経路を一貫して更新する。

1. ゲーム API の ucpl メソッドが Worker 内の実行時パレットを変更する。
2. Worker がフレーム応答に現在のパレット情報、または変更差分を含める。
3. ホスト側が受信データを検証し、通常表示用のパレットを更新する。
4. CRT 表示側にも同じ変更を反映する。必要なら WebGL の色 uniform を更新するか、CRT 描画器を安全に再生成する。
5. 録画・スクリーンショットは既存の表示経路を使い、通常表示と同じ色になることを確認する。

パレット情報は固定長 8 色であるため、初期実装では差分方式よりもフレーム応答に 8 色分を含める単純な方式を優先候補とする。ただし、メッセージ形式・転送量・再生成コストをテストして決定する。

## 8. フレームと更新タイミング

- ゲームコードが ucpl の変更メソッドを呼んだフレームの表示に変更を反映する。
- 変更がないフレームで不要な表示更新を発生させない。
- 複数回呼び出された場合は、同一フレーム内の最後の設定を採用する。
- reset() による標準パレット復元も、通常の色変更と同じタイミングで反映する。

## 9. 互換性と安全性

- 既存の put() / spr() / pcg / BG・MG・FG の動作を変更しない。
- ゲームコードから Canvas、WebGL、ホスト DOM へ直接アクセスさせない。
- Worker とホスト間のメッセージ検証を維持し、パレット配列は長さ 8、各色は 3 成分、各成分は 0〜255 の整数に限定する。
- 標準パレットは変更されない基準値として保持し、実行時パレットとは別に扱う。
- ゲーム終了・再読み込み時は新しいエンジンの標準パレットから開始する。

## 10. テスト項目

### エンジン

- 初期パレットが標準 8 色である。
- ucpl.set(index, r, g, b) が指定色だけを変更する。
- ucpl.setAll(colors) が 8 色すべてを一括設定する。
- setAll() の配列長・各色の要素数・RGB 範囲を検証し、不正入力時に一部だけ反映されない。
- ucpl.get(index) が { r, g, b } 形式の独立した値を返す。
- get() の戻り値を書き換えてもパレット本体が変化しない。
- set() の戻り値が ucpl であり、チェーンできる。
- 色番号 0 と 7 の変更ができる。
- ucpl.reset() で標準 8 色へ復元する。
- 範囲外 index、RGB 成分の範囲外、小数、不足・過剰引数を拒否する。
- ピクセル面の色番号が変わらず、同じ番号の描画済みピクセルが新 RGB で表示される。

### Worker・ホスト・表示

- Worker の初回応答と通常フレーム応答でパレットが正しく伝わる。
- 不正なパレットメッセージを拒否する。
- 通常表示と CRT 表示が同じパレットを使う。
- パレット変更後のスクリーンショット・録画が表示と一致する。
- パレット変更のない既存ゲームで表示結果・性能に退行がない。
- ゲーム再読み込みで標準パレットへ戻る。
