## 11. テスト構成

**優先度：P0 — 変更による退行を検出する品質基盤。**

`tests/` には少なくとも次の領域の検証がある。

- エンジン、描画、文字データ
- ペイロードの圧縮・展開・容量境界
- Runtime、Worker メッセージ、Playback
- 音声処理、録画、Canvas 表示
- エディター補助、サンプル生成
- ビルド、デプロイ設定、サイト、Arcade
- ブラウザ上の操作、デバイス、エラー、隔離、表示品質

テストファイルが存在することと、今回そのテストを実行して成功したことは区別する。GitHub Actions は2つの workflow に分かれる。Pages の Deploy workflow（`.github/workflows/deploy-pages.yml`）では、生成サンプル整合性チェック（`npm run examples:check`）と Node.js 単体テスト（`npm test`）を実行してからビルド・デプロイする。Playwright ブラウザテスト（`npm run test:browser`）は専用 workflow（`.github/workflows/browser-tests.yml`）で実行する。専用 workflow は main への push と workflow_dispatch で起動し、Node.js 24 と Chromium をセットアップする。テスト失敗時は Playwright の診断 artifact を保存する。
