## 11. テスト構成

**優先度：P0 — 変更による退行を検出する品質基盤。**

`tests/` には少なくとも次の領域の検証がある。

- エンジン、描画、文字データ
- ペイロードの圧縮・展開・容量境界
- Runtime、Worker メッセージ、Playback
- 音声処理、録画、Canvas 表示
- エディター補助、サンプル生成
- ビルド、デプロイ設定、サイト、Arcade
- ブラウザ上の操作、デバイス、エラー、隔離、表示品質

テストファイルが存在することと、今回そのテストを実行して成功したことは区別する。GitHub Pages の Deploy workflow では、生成サンプル整合性チェック（`npm run examples:check`）と Node.js 単体テスト（`npm test`）を実行してからビルドする。Playwright ブラウザテスト（`npm run test:browser`）はこの workflow には含めず、別途実行・記録する。
