# PLU 描画機能ロードマップ

> この章は、2026-11-19 時点で話し合った描画機能の拡張候補を分類した構想資料です。優先度は検討の目安であり、実装時期・実装確約を示しません。すべて未実装の候補として扱い、正式仕様は個別設計とテストを経て決定します。

## 1. 方針

PLU の描画機能は、既存 PlayLoad の put() / spr() / pcg を維持しながら、ゲーム作者が少ないコードで多様な表現を作れるよう段階的に拡張する。

- 既存作品との互換性を優先し、既存 API の意味や描画結果を不用意に変更しない。
- PLU 独自 API は上流 PlayLoad の API と衝突しない命名を行う。現時点では u で始まる短い名前を候補とする。
- ゲームコードから Canvas を直接操作させず、エンジン内部のピクセル面・描画経路を通す。
- API を増やすだけでなく、データ形式、描画順、容量、実行時間、テスト方法まで合わせて設計する。
- 「構想」「仕様確定」「実装済み」「検証済み」を明確に区別する。

## 2. 基本図形描画

任意のピクセル座標へ直接図形を描くための候補。

| 機能 | 内容 | API 名候補 | 優先度案 |
| --- | --- | --- | --- |
| 点 | 1 ピクセルを指定色で描画 | upix() | 高 |
| 線 | 2点間の線分 | ulin() | 高 |
| 矩形枠 | 輪郭だけの四角形 | urec() | 高 |
| 塗りつぶし矩形 | 内部を含む四角形 | ubox() | 高 |
| 円 | 円周 | ucir() | 中 |
| 塗りつぶし円 | 内部を含む円 | ufil() | 中 |
| 楕円 | 横長・縦長の円 | 未定 | 中 |
| 三角形・多角形 | 輪郭描画 | upol() など | 中 |
| 塗りつぶし多角形 | 内部を含む多角形 | ufpl() など | 中 |

関数名は候補であり確定していない。矩形の座標指定、線・円・多角形のラスタライズ、塗りつぶし規則、クリッピングを API 設計時に定義する。

## 3. スプライト・画像操作

| 機能 | 内容 | 優先度案 |
| --- | --- | --- |
| 多色スプライト | 1枚の画像内で複数のパレット色を使用 | 高 |
| 透明表現 | 色番号と区別できる透明値・マスクなど | 高 |
| 左右・上下反転 | 元画像データを複製せず反転表示 | 高 |
| 色の置換 | 特定色を別のパレット色へ置換 | 中 |
| 回転 | 指定角度で表示 | 中 |
| 拡大・縮小 | 指定倍率で表示 | 中 |
| 画像コピー・貼り付け | 画像領域やスプライトデータを複製 | 中 |
| 切り抜き | 指定範囲を画像として取り出す | 中 |
| 輪郭・影 | スプライトに輪郭線や影を付ける | 低〜中 |
| 合成 | 複数画像を合成して新しい画像を作る | 低〜中 |

回転・拡大縮小は、回転中心・基準点・補間方式・ピクセルのにじみ・画面外処理・描画負荷を考慮する。既存 spr() は互換性のため維持し、拡張機能は別 API として設計する。

## 4. パレット・色操作

- 実行中に RGB パレットを変更する（ucpl() 候補）。
- グラフィック側の色割り当てを API 化する（ugpl() 候補）。
- 標準パレットへの復元・複数色の一括設定。
- 色の置換、色ごとの透過設定。
- 時間経過に応じたパレットアニメーション。
- グラフィックデータと実 RGB パレットの責務を分離する。

詳細は 15-パレット・多色スプライト・アニメーション構想.md を参照。

## 5. アニメーション・描画効果

### 5.1 アニメーション

- フレーム切り替えによる歩行・攻撃・待機・爆発など。
- フレームごとの表示時間、ループ、再生方向、停止・終了制御。
- 表示／非表示を切り替える点滅。
- パレット色の切り替え、明滅、脈動。
- 拡大率・回転角度などの変形を時間変化させる。

点滅は独立した描画プリミティブではなく、表示状態やパレットを時間変化させるアニメーションの一種として扱う方向。

### 5.2 画面・描画効果

- フェードイン・フェードアウト。
- 画面フラッシュ。
- 画面揺れ。
- 発光・明滅。
- グラデーション。
- 波打ち・歪み。
- モザイク・ノイズ。

効果をスプライト単位・領域単位・画面全体のどこへ適用するかを分けて設計する。重い効果は処理負荷とフレーム安定性を検証してから採用する。

## 6. 描画領域・レイヤー・マップ

- 描画範囲を限定するクリッピング。
- 描画レイヤーの作成、表示／非表示、重ね順。
- 背景・前景・UI などの描画面の分離。
- 描画領域やカメラ位置のスクロール。
- タイルセットとタイルマップの管理・描画。
- タイル単位の反転・回転。

レイヤーやタイルマップは単なる描画関数ではなく、データ管理と描画順序を含む仕組みになるため、独立した設計課題として扱う。

## 7. 文字・表示機能

- 文字サイズ・文字色・背景色の指定。
- 文字の縁取りや影。
- 文字のスクロール。
- UI 用の描画とゲーム画面の描画の使い分け。

既存 put() の互換性を維持しながら、必要性を確認して追加方法を検討する。

## 8. 優先度の考え方

現時点の検討順の目安は次のとおり。

1. 基本図形（点・線・矩形・円）とクリッピング。
2. 多色スプライト、透明表現、反転、パレット操作。
3. フレームアニメーション、点滅、フェードなど基本効果。
4. 画像コピー・貼り付け、回転・拡大縮小。
5. レイヤー、タイルマップ、カメラ・スクロール。
6. 発光・歪み・モザイクなど負荷の高い効果。

これは確定した開発計画ではない。実装の依存関係、既存エンジンとの整合性、利用価値、性能測定によって順序を変更する。

## 9. 共通の設計チェック項目

各機能の仕様を決める際は、少なくとも次を確認する。

- 座標系・単位・整数化・画面外処理。
- 色番号・透明・合成・描画順。
- 既存 put() / spr() / pcg との互換性。
- メモリ・ペイロード容量・書き込み予算。
- 1フレーム当たりの処理量と性能上限。
- API 名の衝突と引数の一貫性。
- 単体テスト・描画結果テスト・実機確認の方法。
- 仕様書・API リファレンス・サンプルの更新。
- 「．えでぃ太」からのデータ出力・読み込みとの整合性。
