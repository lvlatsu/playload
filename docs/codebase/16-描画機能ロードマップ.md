# PLU 描画機能ロードマップ

> この章は、描画機能の現状と今後の拡張候補を整理する資料です。優先度は検討の目安であり、実装時期・実装確約を示しません。2026-11-24 に現行ソース・API リファレンス・テストコードと照合して更新しました。

## 1. 方針

PLU の描画機能は、既存 PlayLoad の `put()` / `spr()` / `pcg` を維持しながら、ゲーム作者が少ないコードで多様な表現を作れるよう段階的に拡張する。

- 既存作品との互換性を優先し、既存 API の意味や描画結果を不用意に変更しない。
- PLU 独自 API は上流 PlayLoad の API と衝突しない命名を行う。原則として小文字 `u` で始まる短い名前を用いる。
- ゲームコードから Canvas を直接操作させず、エンジン内部のピクセル面・描画経路を通す。
- API だけでなく、データ形式、描画順、容量、実行時間、テスト方法まで合わせて設計する。
- 「構想」「仕様確定」「コード実装」「テストコード」「テスト実行」「実機確認」を明確に区別する。

## 2. 実装済みの描画基盤

以下は現行ソースと公開 API リファレンスで実装を確認できる。

| 機能 | API / 内容 | 状態 |
| --- | --- | --- |
| 点 | `upix(x,y,col)` | 実装済み |
| 線 | `ulin(x1,y1,x2,y2,col)` | 実装済み |
| 矩形 | `urec(x,y,w,h,lineCol,fillCol?)` | 実装済み |
| 楕円・正円 | `uelp(x,y,w,h,lineCol,fillCol?)` | 実装済み |
| 3層描画 | `BG` / `MG` / `FG` | 実装済み |
| レイヤー内図形描画 | 各レイヤーの `upix` / `ulin` / `urec` / `uelp` | 実装済み |
| 実行時 RGB パレット | `ucpl.set` / `setAll` / `get` / `reset` | 実装済み |

基本図形の仕様は17章、レイヤーは18章、実行時パレットは20章を参照する。図形 API の塗りつぶしは独立した `ubox` / `ufil` ではなく、`urec` / `uelp` の任意引数で指定する。円は `uelp` の幅・高さを同じにして表現する。

## 3. 今後の拡張候補

### 3.1 スプライト・画像操作

| 機能 | 内容 | 検討事項 |
| --- | --- | --- |
| 多色スプライト | 1枚の画像内で複数のパレット色を使用 | 色深度・透明値・登録方法 |
| 透明表現 | 色番号と区別できる透明値・マスク | 既存の透明背景との整合性 |
| 左右・上下反転 | 元画像データを複製せず反転表示 | 描画 API とデータ API の責務 |
| 色の置換 | 特定色を別のパレット色へ置換 | 対象範囲・実行時負荷 |
| 回転・拡大縮小 | 指定角度・倍率で表示 | 回転中心・補間・ピクセルのにじみ |
| 画像コピー・貼り付け | 画像領域やスプライトデータを複製 | データ容量・コピー規則 |
| 切り抜き | 指定範囲を画像として取り出す | 元データとの関係 |

### 3.2 パレット・色操作

- グラフィック側の色割り当て API（`ugpl` 候補）。
- パレットセットの切り替え・保存・複製。
- 色の置換、色ごとの透過設定。
- 時間経過に応じたパレットアニメーション。

実行時 RGB パレットの初期 API は実装済み。将来のパレットセット機能などは未実装であり、15章・20章の区分を参照する。

### 3.3 アニメーション・描画効果

- フレーム切り替えによる歩行・攻撃・待機・爆発など。
- フレームごとの表示時間、ループ、再生方向、停止・終了制御。
- 表示／非表示を切り替える点滅。
- パレット色の切り替え、明滅、脈動。
- フェード、画面フラッシュ、画面揺れ、発光、グラデーション、波打ち、歪み、モザイク、ノイズ。

汎用アニメーション API や画面効果 API は現時点で未実装。点滅は表示状態やパレットを時間変化させる表現として検討する。

### 3.4 レイヤー・マップ

- レイヤーの表示／非表示、レイヤー単位のクリア。
- スクロール・カメラ位置の制御。
- タイルセットとタイルマップの管理・描画。
- タイル単位の反転・回転。
- レイヤー内容のフレーム間保持。

BG・MG・FG の基本描画先と固定合成順は実装済み。上記の拡張機能は未実装。

### 3.5 文字・表示機能

- 文字サイズ・文字色・背景色の拡張。
- 文字の縁取りや影。
- 文字のスクロール。
- RPG 風の文字送り、ページ送り、メッセージウィンドウ、選択肢。

既存 `put()` の互換性を維持しながら、必要性と責務を整理して設計する。19章は構想のみ。

## 4. 検討順の目安

1. 既存の基本図形・3層描画・実行時パレットの仕様整合性と検証記録を固める。
2. 多色スプライトと透明表現のデータ形式を検討する。
3. 画像データの登録・編集・コピーと「．えでぃ太」からの出力形式を検討する。
4. フレームアニメーションとパレットアニメーションの共通点・相違点を整理する。
5. タイルマップ、カメラ、レイヤー制御、画面効果を必要性に応じて検討する。

これは確定した実装計画ではない。依存関係、利用価値、性能測定によって順序を変更する。

## 5. 共通の設計チェック項目

- 座標系・単位・整数化・画面外処理。
- 色番号・透明・合成・描画順。
- 既存 `put()` / `spr()` / `pcg` との互換性。
- メモリ・ペイロード容量・書き込み予算。
- 1フレーム当たりの処理量と性能上限。
- API 名の衝突と引数の一貫性。
- 単体テスト・描画結果テスト・実機確認の方法。
- 仕様書・API リファレンス・サンプル・開発記録の更新。
- 「．えでぃ太」からのデータ出力・読み込みとの整合性。
