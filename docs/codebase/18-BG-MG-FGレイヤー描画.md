# BG・MG・FG レイヤー描画 実装仕様

> 2026-11-19 実装。現時点のレイヤーAPIは既存スプライト描画を各レイヤーに振り分ける初期版。図形描画、スクロール、表示切替、レイヤー保持は未実装。

## 1. 目的

ゲーム画面を後景・中景・前景の3面に分け、ゲーム作者が描画先を明示できるようにする。

- BG：Background／後景
- MG：Middle／中景
- FG：Foreground／前景

レイヤーの合成順は BG → MG → FG に固定する。ユーザーコード内でメソッドを呼んだ順番がレイヤー間の重ね順を変えることはない。

## 2. ユーザーコード API

各レイヤーに `spr(x, y, str, col)` を提供する。

```js
function tick() {
  BG.spr(0, 0, '★', 2);
  MG.spr(40, 30, 'A', 3);
  FG.spr(80, 60, '✦', 7);
}
```

- 座標は既存 `spr()` と同じピクセル座標。
- 文字列は既存 `spr()` と同じグラフェム単位で配置する。
- 改行、CRLF、画面外クリッピング、色番号の検証も既存 `spr()` と同じ規則。
- 色番号は 0～7。スプライトの背景ビットは透明。
- 各レイヤーは独立した最大128文字分のスプライトキューを持つ。
- キュー上限超過時は既存スプライトと同じグリッチ表現を発生させる。

## 3. フレーム処理

毎フレーム、ユーザーの `tick()` を呼び出す前に、既存スプライトキューと BG・MG・FG の各キューを空にする。

その後、`tick()` が各レイヤーへ描画命令を登録する。レンダリング時は既存の文字画面・既存 `spr()` を描画した後、BG、MG、FG の順に各キューを描画する。

したがって、レイヤー描画は毎フレーム再登録する方式であり、前フレームのレイヤー描画命令は保持しない。固定背景も毎フレーム描画する必要がある。

## 4. 既存 API との互換性

既存の `cls()`、`put()`、`spr()`、`scr`、`pcg` の仕様は変更しない。既存 API は従来どおり使用できる。

既存 API と新レイヤー API を同じフレームで併用した場合、既存の文字画面・既存 `spr()` が先に描画され、その上に BG → MG → FG が重なる。既存 API のみを使うゲームの描画結果は従来どおり。

## 5. 現在の対象外

- `upix()`、`ulin()`、`urec()`、`ubox()`、`ucir()`、`ufil()` などの図形描画
- レイヤー単位のクリア・表示／非表示
- スクロール・カメラ
- レイヤー内容のフレーム間保持
- レイヤー別の描画上限・負荷の最適化

これらは後続の仕様設計・実装で追加する。

## 6. テスト

`tests/engine.test.js` に、固定合成順、フレームごとのキュー初期化、複数行文字列、引数検証のテストを追加した。実行環境でのテストスイート・ブラウザー表示確認は別途実施する。
