# BG・MG・FG レイヤー描画 実装仕様

> 状態：実装済み。初期のスプライト専用仕様から、基本図形 API も各レイヤーで利用できる仕様へ拡張済み。ソース・API リファレンス・テストコードを照合して2026-11-24更新。テスト実行・実機確認は別途。

## 1. 目的

ゲーム画面を後景・中景・前景の3面に分け、ゲーム作者が描画先を明示できるようにする。

- BG：Background／後景
- MG：Middle／中景
- FG：Foreground／前景

レイヤーの合成順は BG → MG → FG に固定する。ユーザーコード内で異なるレイヤーのメソッドを呼んだ順番が、レイヤー間の重ね順を変えることはない。

## 2. ユーザーコード API

各レイヤーで既存スプライト API と基本図形 API を利用できる。

| API | 引数 |
| --- | --- |
| `BG.spr()` / `MG.spr()` / `FG.spr()` | `spr(x, y, str, col)` |
| `BG.upix()` / `MG.upix()` / `FG.upix()` | `upix(x, y, col)` |
| `BG.ulin()` / `MG.ulin()` / `FG.ulin()` | `ulin(x1, y1, x2, y2, col)` |
| `BG.urec()` / `MG.urec()` / `FG.urec()` | `urec(x, y, w, h, lineCol, fillCol?)` |
| `BG.uelp()` / `MG.uelp()` / `FG.uelp()` | `uelp(x, y, w, h, lineCol, fillCol?)` |

使用例：

```js
function tick() {
  BG.spr(0, 0, '★', 2);
  BG.uelp(70, 20, 40, 20, 7, 2);
  MG.urec(20, 30, 40, 24, 3, 4);
  MG.ulin(0, 0, 80, 80, 6);
  FG.upix(80, 60, 7);
}
```

各 API の座標・色・塗りつぶし・エラー規則は17章を参照する。レイヤー API は通常 API と同じ引数・描画規則を使う。

## 3. フレーム処理と描画順

毎フレーム、ユーザーの `tick()` を呼び出す前に、通常スプライトキューと BG・MG・FG の各描画キューを空にする。

その後、`tick()` が各描画先へ命令を登録する。レンダリング時は次の順で描画する。

1. 文字画面（`cls()` / `put()` / `scr`）
2. 通常描画面（`spr()` と `upix` / `ulin` / `urec` / `uelp`）
3. BG
4. MG
5. FG

BG・MG・FG の各レイヤー内では、スプライトと図形命令の登録順を維持する。したがって同じレイヤーでは後から登録した描画命令が上に重なる。レイヤー間は常に BG → MG → FG の固定順となる。

各描画キューは毎フレーム初期化される。固定背景も表示を続けるには毎フレーム登録する必要がある。各キューは1フレーム最大128命令で、超過時は既存のグリッチ通知方式を使う。

## 4. 既存 API との互換性

既存の `cls()`、`put()`、`spr()`、`scr`、`pcg` は引き続き利用できる。通常の文字画面・スプライト描画が先に描画され、その上に BG → MG → FG が重なる。既存 API のみを使うゲームの描画結果を不用意に変更しない。

## 5. 現時点の対象外

- レイヤー単位のクリア API、表示／非表示
- スクロール・カメラ
- レイヤー内容のフレーム間保持
- タイルマップ・タイルセット
- レイヤーごとの描画上限設定・負荷最適化
- レイヤーの任意作成・任意の重ね順変更
