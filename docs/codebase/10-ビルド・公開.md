## 10. ビルド・公開

**優先度：P0 — 配布物の生成と公開に直結。**

### 10.1 開発環境

`package.json` の主要情報:
- Node.js: 24 以上
- モジュール形式: ES Modules
- バンドラー: esbuild
- テスト: Node.js test runner、Playwright
- 静的解析: ESLint
- 書式: Prettier

主要コマンド:
| コマンド | 目的 |
| --- | --- |
| `npm run dev` | Wrangler のローカル開発サーバー |
| `npm run examples:check` | サンプル一覧の生成物が元データと一致するか確認 |
| `npm run build` | `dist/` へサイトをビルド |
| `npm test` | Node.js の単体テスト |
| `npm run test:browser` | Playwright ブラウザテスト |
| `npm run lint` | ESLint |
| `npm run check` | lint、format、生成物検査、各種テストを一括実行 |
| `npm run deploy:check` | check と Wrangler dry-run |
| `npm run deploy` | 検査後 Wrangler でデプロイ |

### 10.2 ビルド処理

`scripts/build.js` は esbuild でアプリ、サイト、Arcade、スタイル、Worker をバンドルする。テンプレートへ生成値を埋め込み、`dist/playload/` 以下に公開用ファイルを構築する。Worker はビルド時にバンドルされ、sandbox のホストスクリプトへ埋め込まれる。sandbox 文書には生成した CSP が設定される。

ビルドは一時ディレクトリに生成してから出力先を置き換える。出力先がリポジトリ内の許可されない場所やソースを上書きする場所にならないよう検査する。

### 10.3 GitHub Pages

`.github/workflows/deploy-pages.yml` は `main` と `plu/gem-survivor-preset` への push、および手動実行でビルドジョブを開始する。成果物は `dist/playload`。依存関係の導入後に `npm run examples:check` でサンプル一覧の生成物を検査し、`npm test` で Node.js 単体テストを実行してから `npm run build` を実行する。デプロイジョブは `main` ブランチの場合に限り実行される。

Playwright ブラウザテストは `.github/workflows/browser-tests.yml` で別途実行する。main への push または手動実行で Node.js 24 と Chromium をセットアップし、`npm run test:browser` を実行する。失敗時は `playwright-report/` と `test-results/` を診断 artifact として保存する。

`package.json` の homepage は `https://lvlatsu.github.io/playload/` で、ビルドは公開パス `/playload/` を前提にしている。

### 10.4 Wrangler 設定上の注意

`wrangler.jsonc` には `kitao.dev/playload*` の Cloudflare Workers ルートが記載されている。これはフォーク元由来の設定を含む可能性があり、GitHub Pages の公開設定とは別系統である。Cloudflare へのデプロイを実行する場合は、対象ドメイン・アカウント・権限・公開先を必ず確認する。現状のコード調査だけでは Cloudflare へのデプロイ実績を示さない。
