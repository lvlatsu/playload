## 4. ゲームエンジンと描画経路

**優先度：P0 — ゲームの実行結果と表示を決める中核。**

### 4.1 エンジン内部

`createEngine()` は 160×144 = 23,040 要素の `Uint8Array` をピクセル面として保持する。各要素は 0〜7 のパレット番号である。

文字画面は 20×18 セルで構成され、各セルは文字と前景色・背景色を保持する。文字の字形は 8 行の 8-bit パターンとして管理される。スプライトは毎フレームの一時描画リストとして保持される。

### 4.2 描画処理

1. 文字画面の各セルについて、文字パターンを 8×8 ピクセルへ展開する。
2. そのフレームのスプライトを重ねる。
3. 描画結果をパレット番号のピクセル配列として返す。
4. アプリ側の表示層が Canvas に反映する。

ゲームコードが画面の Canvas へ直接描く構造ではない。ゲーム API の描画命令はエンジン内のピクセル配列へ反映され、Canvas はアプリ側の出力先である。

### 4.3 Canvas 表示

- 通常表示: `display.js` が 8 色のパレットを RGBA に変換し、最近傍拡大した `ImageData` をメイン Canvas へ `putImageData()` する。
- CRT 表示: `crt.js` が別の WebGL Canvas で CRT シェーダーを適用し、メイン Canvas へ `drawImage()` する。
- 撮影: `capture.js` がメイン Canvas の `captureStream(60)` を使い、対応時は音声ストリームも合成する。
- スクリーンショット: メイン Canvas を画像 Blob として保存する。

このため、描画機能を拡張する場合も、既存のピクセル面へ描画結果を統合する方式が、CRT・録画・スクリーンショットとの整合性を保ちやすい。ただし、追加の図形描画 API は現時点では実装されていない。

### 4.4 既存の描画上限

`docs/design.md` とエンジン実装では、スプライト数、PCG 書き込み量、変更可能な文字種類に上限がある。超過時はグリッチ表現が発生する。詳細値や計数方法を変更する際は、設計文書と `tests/engine.test.js` 等の対応テストを同時に確認する。
