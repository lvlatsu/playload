# PLU 基本図形描画 API 仕様案

> 状態：仕様策定案。2026-11-19 時点では未実装・未検証。ここに記す関数名・引数・描画規則は、実装前にコード構造と既存 API リファレンスを再確認したうえで確定する。

## 1. 目的と設計方針

既存の put() / spr() / pcg を維持したまま、ゲームコードから任意のピクセル座標へ基本図形を描けるようにする。

- 描画先は既存の 160×144 ピクセル面とし、ゲームコードから Canvas を直接操作させない。
- 座標単位はピクセル。文字セルや 8×8 スプライト単位ではない。
- 描画関数は呼び出された順に反映する。
- 画面外の部分は描画せず、画面内の部分だけを残す（クリッピング）。
- 既存 API の動作・描画順・互換性を変更しない。
- まず整数座標・単色描画に限定し、アンチエイリアスや線幅などは初期仕様に含めない。

## 2. API 一覧と引数案

| API | シグネチャ案 | 動作 |
| --- | --- | --- |
| 点 | upix(x, y, col) | 1 ピクセルを描く |
| 線 | ulin(x1, y1, x2, y2, col) | 2点間を結ぶ線分を描く |
| 矩形枠 | urec(x, y, w, h, col) | 幅 w・高さ h の矩形の輪郭を描く |
| 塗りつぶし矩形 | ubox(x, y, w, h, col) | 幅 w・高さ h の矩形全体を塗る |
| 円周 | ucir(cx, cy, r, col) | 中心 (cx, cy)、半径 r の円周を描く |
| 塗りつぶし円 | ufil(cx, cy, r, col) | 中心 (cx, cy)、半径 r の円を塗る |

引数名は説明用。正式な公開名・引数名は実装と API リファレンス更新時に確定する。

## 3. 共通ルール案

### 3.1 座標と数値

- x は左から右、y は上から下へ増加する。
- 画面内の有効座標は x=0〜159、y=0〜143。
- 座標・幅・高さ・半径は有限の数値を受け取り、整数化して扱う。
- 初期案では小数は 0 方向への切り捨て（Math.trunc 相当）とする。丸め方式は全 API で統一する。
- NaN、Infinity、数値以外など不正な値を含む呼び出しは何も描かず、安全に終了する。
- 巨大な値による過剰ループを避けるため、アルゴリズムは画面範囲に対して計算量を制限する。単純に入力座標間を全走査しない。

### 3.2 色

- col は 0〜7 のパレット番号とする。
- 図形描画では色 0 も通常の色として描画する。透明扱いにはしない。
- 色番号が整数範囲外、または不正な値の場合は何も描かない案とする。
- RGB の実色定義や実行中パレット変更は、この API の責務に含めない。パレット API の章で別途定義する。

### 3.3 クリッピングと描画順

- 描画対象が画面外にはみ出した場合、画面内のピクセルだけを描く。
- 画面外への描画を理由に例外を発生させない。
- 図形同士が重なった場合、後から呼ばれた描画関数の色が残る。
- 既存 put() / spr() / PCG の合成順は変更しない。図形描画を既存描画とどの段階で合成するかは、実装前に現在のフレーム描画処理を確認して確定する。

## 4. 個別の描画規則案

### 4.1 upix(x, y, col)

- 指定座標の 1 ピクセルだけを描く。
- 座標が画面外なら何もしない。
- 他の図形 API の基本操作として内部共通化できる設計にする。

### 4.2 ulin(x1, y1, x2, y2, col)

- 始点・終点を含む 1 ピクセル幅の線分を描く。
- 初期案は整数ラスタライズの Bresenham 系アルゴリズムとする。
- 水平・垂直・斜め・逆方向の線で一貫した結果にする。
- 画面外を含む非常に長い線分は、描画前に画面範囲へクリップするか、画面内ピクセル数に比例する処理にする。

### 4.3 urec(x, y, w, h, col)

- (x, y) を左上とする幅 w・高さ h の矩形を描く。
- 幅・高さはピクセル数。右端は x+w-1、下端は y+h-1 とし、終端座標を別引数にはしない。
- w または h が 1 の場合も有効。0 以下は何も描かない。
- 四辺が重なる角は同じ色なので、重複書き込みを避けても結果は同じ。

### 4.4 ubox(x, y, w, h, col)

- urec と同じ矩形範囲を内部まで塗る。
- 幅・高さが 0 以下なら何も描かない。
- 画面外の範囲を先に切り詰め、画面内の領域だけを処理する。

### 4.5 ucir(cx, cy, r, col)

- 中心 (cx, cy)、半径 r の円周を描く。
- 初期案は整数演算による中点円アルゴリズムとする。
- r=0 は中心の 1 ピクセルを描く。負の半径は何も描かない。
- 対称点の重複描画は結果に影響しないが、不要な書き込みを避ける。

### 4.6 ufil(cx, cy, r, col)

- ucir と同じ中心・半径で内部を塗る。
- 初期案は各 y 行の左右端を求めて水平線分を描く方式など、画面範囲に対して処理量を制限できる方法とする。
- r=0 は中心の 1 ピクセル。負の半径は何も描かない。

## 5. 初期版で扱わない機能

次の機能は基本図形 API の初期版に含めず、必要性と性能を確認して別途設計する。

- 線幅、破線、点線、線端・角のスタイル
- アンチエイリアス、サブピクセル座標
- グラデーション、アルファブレンド、半透明
- 塗りつぶしパターン・テクスチャ
- 楕円、多角形、ベジェ曲線
- 任意のクリッピング領域を指定する API
- 図形の読み取り・ヒットテスト

## 6. 性能・安全性

- ゲーム画面は 160×144 の固定サイズであるため、描画処理は画面内のピクセル数に比例する上限を持つようにする。
- 入力値が極端に大きくても、入力値の大きさに比例した無制限ループを発生させない。
- 1フレームに大量の図形を描くケースを想定し、ベンチマークまたは上限テストを追加する。
- 内部描画バッファの境界チェックを徹底し、配列外書き込みを防ぐ。
- ゲームコードから渡された値を前提なしに信用せず、Worker 内のゲーム API 境界で検証する。

## 7. テスト項目案

### 7.1 正常系

- 四隅・画面中央への点描画。
- 水平、垂直、正負の傾き、始点と終点を逆にした線。
- 1×1、1×N、N×1、通常サイズの矩形。
- 半径 0、小さい円、画面内に収まる円。
- 色 0 と色 7 を含む全色番号。

### 7.2 境界・異常系

- 左右上下の画面境界に接する図形。
- 一部または全部が画面外にある図形。
- 負の座標、負の半径、幅・高さ 0 以下。
- NaN、Infinity、文字列、未指定引数。
- 極端に大きな座標・幅・高さ・半径。
- 不正な色番号。

### 7.3 互換性・性能

- 既存 put() / spr() / pcg の描画結果が変わらないこと。
- 既存ゲームのペイロード・共有 URL が変化しないこと。
- 既存の描画順、CRT 表示、録画、スクリーンショット経路への影響。
- 多数の図形を連続描画した場合のフレーム時間。
- テストは内部バッファの期待値確認を基本とし、必要に応じて描画画像の比較を追加する。
