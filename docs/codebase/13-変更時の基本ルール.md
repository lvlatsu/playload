## 13. 変更時の基本ルール

**優先度：P0 — 互換性・安全性・品質を守る共通ルール。**

1. 変更前に対象ファイルと責務を特定し、関連する仕様書・API リファレンス・テストを読む。
2. 実装前に、今回の変更範囲・変更しない範囲・受け入れ条件を明確にする。
3. API の変更は既存 API リファレンスと互換性への影響を別途確認する。
4. 生成物は生成元・生成スクリプトから更新する。
5. Worker 境界の変更はホストと Worker の両側で検証する。
6. 描画変更は通常表示、CRT、録画、スクリーンショットを含めて確認する。
7. ペイロード変更は新旧 URL、圧縮上限、URL 長、展開後上限を確認する。
8. 公開設定変更は GitHub Pages と Wrangler を混同せず、公開先を確認する。
9. 実行していないテストや実機確認を、完了済みとして記録しない。
10. 実装後はソース・テスト・API リファレンス・関連仕様書・開発記録を同じ変更単位で更新する。
11. 作業終了時に「実装」「テストコード追加」「テスト実行」「実機確認」「デプロイ」を分けて報告する。
12. 次の担当者が再開できるよう、未完了事項と次の具体的な作業を記録する。

## 13.1 PLU 独自 API の命名規則

PLU 独自 API は、オリジナル PlayLoad の API との名前衝突を避け、将来の上流側の機能追加とも共存しやすくするため、次の命名方針を基本とする。

- 関数名は **小文字の `u` で始める**。
- 関数名は **原則4文字** とする。
- `u` は Unlimited を表す PLU 独自拡張の識別子とする。
- 既存の PlayLoad API と同名にならないことを実装前に確認する。
- 4文字に収まらないなどの例外を設ける場合は、理由を API リファレンスに明記する。
- この規則は PLU 独自 API に適用し、オリジナル PlayLoad 由来の API 名は変更しない。

### 実装済みの命名例

| API | 役割 |
| --- | --- |
| `upix()` | 1ピクセル描画 |
| `ulin()` | 線分描画 |
| `urec()` | 矩形描画 |
| `uelp()` | 楕円・正円描画 |
| `ucpl` | 実行時 RGB パレット操作オブジェクト |
| `urnd()`、`usin()`、`ucos()` など | 数学 API |

### 未確定の候補

| 候補 | 想定する機能 | 状態 |
| --- | --- | --- |
| `upol()` | 多角形の輪郭描画 | 未確定 |
| `ufpl()` | 塗りつぶし多角形 | 未確定 |
| `ugpl()` | グラフィック側パレット操作 | 構想 |
| `utxt()` / `utyp()` | テキスト・文字送り | 構想 |

矩形の塗りつぶしは `urec()` の任意引数、楕円・円の塗りつぶしは `uelp()` の任意引数として扱う。旧案の `ubox()`、`ucir()`、`ufil()` は現行 API ではない。
