## 13. 変更時の基本ルール

**優先度：P0 — 互換性・安全性・品質を守る共通ルール。**

1. 変更対象の責務を持つファイルを特定し、隣接するテストを確認する。
2. API の変更は既存 API リファレンスと互換性への影響を別途確認する。
3. 生成物は生成元・生成スクリプトから更新する。
4. Worker 境界の変更はホストと Worker の両側で検証する。
5. 描画変更は通常表示、CRT、録画、スクリーンショットを含めて確認する。
6. ペイロード変更は新旧 URL、圧縮上限、URL 長、展開後上限を確認する。
7. 公開設定変更は GitHub Pages と Wrangler を混同せず、公開先を確認する。
8. 実行していないテストや実機確認を、完了済みとして記録しない。

## 13.1 PLU 独自 API の命名規則

PLU 独自 API は、オリジナル PlayLoad の API との名前衝突を避け、将来の上流側の機能追加とも共存しやすくするため、次の命名方針を基本とする。

- 関数名は **小文字の `u` で始める**。
- 関数名は **原則4文字** とする。
- `u` は Unlimited を表す PLU 独自拡張の識別子とする。
- 既存の PlayLoad API と同名にならないことを実装前に確認する。
- 4文字に収まらないなどの例外を設ける場合は、理由を API リファレンスに明記する。
- この規則は PLU 独自 API に適用し、オリジナル PlayLoad 由来の API 名は変更しない。

### 命名例（候補）

| API 名 | 想定する機能 |
| --- | --- |
| `ulin()` | 線の描画 |
| `urec()` | 矩形枠の描画 |
| `ubox()` | 塗りつぶし矩形の描画 |
| `ucir()` | 円の描画 |
| `ufil()` | 塗りつぶし円の描画 |
| `upol()` | 多角形の描画 |
| `ufpl()` | 塗りつぶし多角形の描画 |

> 上記は命名方針を示す候補例であり、API の実装済み・正式確定を意味しない。引数、境界条件、描画仕様などの正式な定義は API リファレンスで行う。
