## 13. 変更時の基本ルール

**優先度：P0 — 互換性・安全性・品質を守る共通ルール。**

1. 変更対象の責務を持つファイルを特定し、隣接するテストを確認する。
2. API の変更は既存 API リファレンスと互換性への影響を別途確認する。
3. 生成物は生成元・生成スクリプトから更新する。
4. Worker 境界の変更はホストと Worker の両側で検証する。
5. 描画変更は通常表示、CRT、録画、スクリーンショットを含めて確認する。
6. ペイロード変更は新旧 URL、圧縮上限、URL 長、展開後上限を確認する。
7. 公開設定変更は GitHub Pages と Wrangler を混同せず、公開先を確認する。
8. 実行していないテストや実機確認を、完了済みとして記録しない。
