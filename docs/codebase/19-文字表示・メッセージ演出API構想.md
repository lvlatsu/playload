# PLU 文字表示・メッセージ演出 API 構想

> 2026-11-19 時点の構想メモ。ここに記載する API 名・引数・動作は候補であり、正式仕様・実装済み機能ではない。

## 1. 目的

既存の `put()` による文字表示を補完し、RPG の会話ウィンドウのような「一文字ずつ表示されるメッセージ」を簡単に実装できる API を検討する。

単なる文字列の描画だけでなく、会話・イベント・チュートリアルなどの演出に利用できることを目指す。

## 2. API 名候補

| API | 役割 | 状態 |
| --- | --- | --- |
| `utxt(x, y, text, color)` | 通常のテキスト表示 | 候補 |
| `utyp(...)` | 文字送り付きメッセージ表示 | 候補 |

名前・引数・戻り値は未確定。既存の `put()` と役割が重ならないよう、文字座標／ピクセル座標、画面への直接描画／メッセージ制御の責務を整理してから決定する。

## 3. 文字送りの基本イメージ

指定した文章を、一定フレーム間隔で一文字ずつ表示する。

- 表示開始時は先頭の文字だけを表示する。
- フレームの経過に応じて表示文字数を増やす。
- 指定した速度で全文を表示する。
- 表示状態や進行位置はエンジン側で管理し、ユーザーコードが毎フレーム文字数を数えなくても使える形を目指す。

仮の利用イメージ：

```js
function tick() {
  utyp(8, 100, "こんにちは！", 2);
}
```

上記は API の方向性を示す擬似例。引数の意味・速度の単位・毎フレーム呼び出す方式かどうかは未決定。

## 5. 設計時の確認事項

- 文字座標とピクセル座標のどちらを使うか。
- 1文字あたりの待ち時間・速度指定の単位。
- 日本語、絵文字、結合文字などを「一文字」と数える単位。
- 改行・画面端・長文の扱い。
- `tick()` から毎フレーム呼ぶ場合の状態保持方法。
- 同時に複数のメッセージを扱えるか。
- ボタン入力との連携、スキップ・ページ送りの責務。
- 既存 `put()` / `spr()` と描画順・色指定の整合性。
- レイヤー BG / MG / FG のどこへ描画するか、または専用 UI 面を設けるか。
- 効果音を文字単位で鳴らす場合の音声負荷・連続再生制御。
