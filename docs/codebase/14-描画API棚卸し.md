# PLU 描画 API 棚卸し

> この文書は、2026-11-19 時点の `main` ブランチを対象に、公開 API リファレンス・エンジン実装・テストから描画機能を整理したものです。正式な API 契約は `data/reference.json` と対応する実装・テストを正とします。

## 1. 現在の描画関連 API

| API | 状態 | 現在の役割 | 描画上の特徴・制約 |
| --- | --- | --- | --- |
| `cls(col)` | 実装済み | 文字画面全体を指定色で塗る | 20×18 セルを空白文字にする。独立したピクセル面を直接クリアする API ではない |
| `put(cx, cy, str, col1?, col2?)` | 実装済み | 文字画面へ文字列を配置する | 文字座標。改行対応。セル単位で前景色・背景色を指定できる |
| `spr(x, y, str, col)` | 実装済み | 8×8 字形をピクセル座標へ配置する | 8 ピクセル刻み。背景は透明。1 フレーム最大 128 文字 |
| `pcg[chr].pat` | 実装済み | 文字ごとの 8×8 ドットパターンを定義する | 8 行×8 bit。文字パターンの変更は書き込み予算を消費する |
| `pcg[chr].col` | 実装済み | 文字の標準前景色・背景色を設定する | 0〜7 のパレット番号。パターンと色は同じ書き込み予算を共有 |
| `scr[cy][cx]` | 実装済み | 文字画面のセルを直接参照・編集する | 文字とセル単位の色を保持。文字座標で扱う |

### 関連する固定仕様

- ゲーム画面は 160×144 ピクセル、パレットは 8 色。
- 文字画面は 20×18 セル。各文字パターンは 8×8 ピクセル。
- `spr` は毎フレームの一時描画。文字画面の内容は保持される。
- `pcg` のパターン・色の書き込みは、1 フレーム 256 bytes、実行中に変更できる文字 256 種類の制限を共有する。
- 描画結果はエンジン内部のパレット番号ピクセル配列へ展開され、アプリ側が Canvas に表示する。

## 2. 現時点で確認できない／存在しない描画 API

公開 API リファレンスとエンジンのゲーム API に、次のような汎用図形描画関数は確認できない。

| 機能 | 現状 | PLU 独自 API の候補 |
| --- | --- | --- |
| 1 ピクセル描画 | 専用 API なし | `upix()`（候補・要検討） |
| 線分 | 専用 API なし | `ulin()` |
| 矩形枠 | 専用 API なし | `urec()` |
| 塗りつぶし矩形 | 専用 API なし | `ubox()` |
| 円 | 専用 API なし | `ucir()` |
| 塗りつぶし円 | 専用 API なし | `ufil()` |
| 多角形 | 専用 API なし | `upol()` |
| 塗りつぶし多角形 | 専用 API なし | `ufpl()` |

上記の名前は命名規則に沿った候補であり、正式決定・実装済みを意味しない。特に `upix()` は、既存の `pcg` / `spr` との役割分担を決めてから採否を判断する。

また、ゲームコードから直接利用できる次の機能も、現行 API としては確認できない。

- 実ピクセル配列への直接アクセス・任意のピクセル読み書き
- 任意サイズの画像・ビットマップを一括転送する API
- パレット色そのものをゲーム実行中に変更する API
- 塗りつぶし境界探索（バケツ塗り）API
- 描画領域・クリッピング領域を指定する API

## 3. 棚卸しから分かること

現行 API は、**8×8 の文字・字形を組み合わせて画面を作る方式**が中心である。個々のゲーム作者が独自に点・線・多角形などのラスタライズ処理を実装すれば表現できるが、共通 API としては提供されていない。

PLU の図形描画 API は、既存の文字・スプライト・PCG の仕組みを置き換えるものではなく、任意座標の図形を簡潔に描くための補完機能として設計する。

実装する場合は Canvas へ直接描かず、既存の 160×144 ピクセル面へ描画する。これにより通常表示、CRT、録画、スクリーンショットの既存経路を維持する。

## 4. 次に API 設計で決めること

実装に入る前に、各関数について次を定義する。

1. 引数の順序と省略可能な値（特に色）。
2. 座標・幅・高さ・半径の整数化規則。
3. 矩形の終端を含むか、幅・高さで指定するか。
4. 線・円・多角形のラスタライズ規則。
5. 画面外にはみ出した場合のクリッピング。
6. 塗りつぶしの重なり順と色 0 の扱い。
7. 異常値・巨大な入力に対する上限とエラー処理。
8. 既存 API・上流 PlayLoad の将来追加との名前衝突確認。
9. 描画量がゲームの実行時間やフレーム安定性へ与える影響。

この棚卸しはソース確認に基づくものであり、実機での最新動作確認を完了したという意味ではない。
